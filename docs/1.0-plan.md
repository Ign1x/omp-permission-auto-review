# Permission manager 1.0.0

Approved implementation plan: exactly seven feature commits from `ca9733f`,
then push the branch and annotated tag `1.0.0`. Each commit includes its relevant
tests and documentation. Existing uncommitted read/progress drafts are integrated
into their corresponding features; they are not extra commits.

1. [x] Separate local policy, model reviewer and approval orchestration; add workspace reads.
2. [x] Scoped command/path rules, conservative compound parsing, and policy explanation.
3. [x] Explicit session approvals, persistent scoped rules, listing and revocation.
4. [x] Bounded attributed authorization context, retained restrictions and stale-decision checks.
5. [ ] One total review deadline, bounded retries and cancellation.
6. [ ] Approval choices, review progress, manual takeover and diagnostics.
7. [ ] Permission presets, advanced settings, provenance, migration docs and 1.0.0 release validation.

Design reference: [OpenAI Codex c248f6d](https://github.com/openai/codex/tree/c248f6d48b97eb4a2aa56147a0b11b7d763278b9),
especially tool orchestration, execution policy, approval caching, Guardian
context/retry handling, approval overlays and permission presets. The adaptation
uses OMP's extension API and keeps a single `tool_call` handler.

The extension is a permission gate, not an OS sandbox. Scoped file permissions
apply to supported, trusted OMP tools. Arbitrary shell commands require explicit
rules or review; execution-layer sandbox integration is outside this release.

Validation: type checking and all tests before each commit; dedicated bypass,
precedence, stale authorization, cancellation and configuration migration cases.
Final checks include exactly seven commits, a clean tree, package version 1.0.0,
and remote branch/tag verification. Never force-push or replace an existing tag.
